01 / PURPOSEWhat this project does

WorldLitter models the movement of particles released from coastal and river sources using ocean surface velocity fields. Its scripts turn simulated trajectories into maps, spatial histograms, and compact files for a marine-litter web visualizer.

A separate reporting workflow reads precomputed country-to-country litter statistics and formats them as JSON, CSV, figures, dashboards, and PDF tables. Those statistics are imported from an external workflow; the inspected table scripts do not derive them directly from this repository’s trajectory files.

Surface transport

Advection, optional random diffusion, and optional movement away from stranded locations.

Monthly releases

Separate release cohorts, run through a common end date using restartable segments.

Two output families

Particle trajectories and visualizations; country statistics and reports.

Current checkout: useful code and local datasets are present, but execution needs configuration reconciliation and external inputs. Most simulation modules import WorldLitter; config/params.py currently defines GlobalModel instead. This summary documents the existing state; simulation execution was not validated.

02 / DATA FLOWHow the pieces connect

01 → Prepare inputsCoordinates + velocity fields

Coast/river CSVs supply particle positions. HYCOM NetCDF files supply surface motion. GIS polygons associate particles with countries and oceans.

02 → SimulateOceanParcels integration

1_WorldLitter.py calls models.sequential(), selects kernels, and writes trajectory segments.

03 → AssembleRestart and merge

2_MergeRuns.py joins segments within a release. Script 7 appends an additional period to an existing merged release.

04 → ExportMaps, histograms, web data

Scripts 3–6 create images, binary coordinates, headers, and gridded accumulated-location products.

Country metadata branch

Release CSVs + country/ocean polygons → 0_1_Combine_Locations_with_Countries_and_Oceans.py → country-to-particle index CSV → country-grouped trajectory exports. Particle order must stay consistent between the release files, simulation, and index CSV.

Country statistics branch

External sum_from_*.txt / sum_to_*.txt → Tables_1_Make_Tables_by_Country.py → ReachedTablesData.json/.csv → Plotly images, Dash tables, and PDF reports.

Sources: simulation entry point, model assembly, statistics parser.

06 / NUMERICAL MODELConfiguration and transport behavior

The model follows positions through time using a fourth-order Runge–Kutta advection kernel. The winds flag changes the forcing folder to YYYYc; wind velocity is already combined with currents in those files. It does not add a wind term inside the main simulation.

SettingValue / behavior in inspected code
Integration / output intervaldt = 1 hour; saved positions every 24 hours in active and example configurations.
Release repetitionActive/HPC configuration uses repeat_release = None. Batch jobs create separate monthly cohorts. MainConfigExample.py uses False instead.
Forcing yearsmodels.sequential() computes years from the requested start/end dates; it does not use the configuration’s years entry. Time extrapolation is enabled on the velocity field.
DiffusionUniform stochastic displacement uses Kh_zonal and Kh_meridional, both initialized with kh = 1 in the model. It uses Parcels’ spherical field conversions.
UnbeachingCustom LitterParticle adds integer beached and beached_count. Near-zero velocity triggers movement with the unbeaching field. A count threshold based on 10 days marks state 4; particle deletion is commented out.
Boundary handlingA zonal periodic halo wraps longitude. The out-of-bounds handler sets particle.beached = 4, including in runs that select plain JITParticle; that combination needs validation.
Wind preparationThe helper Combine_Currents_And_Winds_netcdf.py sets a 2.5% wind contribution and 15° deflection with opposite hemisphere signs. Reader comments describe 1% combined inputs. The actual forcing files determine which settings apply.

Sources: active local configuration, model setup, kernels, wind preparation.

07 / EXECUTIONRun, restart, merge

The CLI expects timestamps with an hour suffix, YYYY-MM-DD:HH. Its positional signature is:

python 1_WorldLitter.py START END WINDS DIFFUSION UNBEACHING NAME [RESTART_FILE EXECUTION_DAYS]

For example, after repairing the configuration and preparing inputs:

# Illustrative 30-day segment: currents + winds + diffusion
python 1_WorldLitter.py 2010-01-01:00 2010-01-31:00 True True False example_2010_01

# Restart arguments must be supplied together.
python 1_WorldLitter.py 2010-01-31:00 2010-03-02:00 True True False example_2010_01 /path/to/previous.nc 30

These are interface examples, not commands verified to run in the current checkout. A missing restart path causes a fresh release rather than a hard failure. Output naming needs attention: the model writes to output_folder/name, whereas restart and merge code append config[output_file]. The HPC template uses .nc; the active local config supplies a full run-specific filename.

HPC orchestration

HPC_RUN.sh currently expands all months of 2010–2022 into 156 jobs, substitutes YEAR/MONTH in generalrun_hpc.sh, and submits each with sbatch. The active branch starts new runs. The template requests 32 tasks, one node, 64 GB, 20 hours, and partition coaps_q; it invokes the historical environment /gpfs/home/osz09/.conda/envs/py3_parcels_mpi/bin/python.

The template advances in 30-day segments through 2023-01-01, with flags True True False. Its final merge command is commented out. The extra-year template instead begins on 2022-01-01, restarts from output_final, writes output_2022, and invokes the two merge stages. These dates and resources are saved settings, not evidence that jobs completed.

Country reporting

The active table-generation loop reads scenario prefixes C, D, and I for 2017–2022 and writes one JSON/CSV pair under each <letter><year>_12 directory. Source comments describe multiple decay scenarios, but their numerical definitions are not established by this parser. Tables_2_MakeTables_PngsForPDF_Plotly.py then renders PNG tables with Kaleido and calls the PDF helper. The Dash script reads a hard-coded 2022 output.

08 / PRODUCTSWhat the outputs contain

Output location: project outputs are stored on the COAPS host mars.coaps.fsu.edu, as confirmed by the project owner. See Path reference for the output directories recorded in the configuration and README.

Trajectories: NetCDF and optional Zarr

Merge scripts expect traj × obs arrays for time, trajectory, lat, lon, and z, plus beached/beached_count for unbeaching runs. Script 2 removes duplicate segment-boundary observations. Script 7 directly concatenates older and newer periods, so their boundary times should be checked for overlap. 0_UpdateToZarr.py provides an optional storage conversion.

Web particles: binary arrays and text headers

Script 4 groups particles by country, subsamples indices while reducing the stride for countries with fewer particles, and encodes latitude and longitude × 100 as signed 16-bit integers. Each header row records country, continent, number of particles, and number of time steps. Arrays store each country’s latitude block followed by its longitude block.

The active multi-file exporter uses a subsampling stride of 2 and chunks of 500 observations, writing …_00.bin and …_00.txt under a stride directory. Its ZIP-writing block is commented out; the single-file function also writes a ZIP. Despite the script’s name, this is not a trajectory JSON export.

Spatial histograms: accumulated occupancy

Script 5 bins all saved particle positions on a 0.1° grid. It scales accumulated counts by 6.5e6 / (number_of_particles × 12), adds 1, and masks empty cells. This hard-coded mass scaling assumes 12 releases per year; it is not sourced from the release weight files. Interpret it as the implemented accumulated-location product, with its sampling and scaling assumptions, rather than a validated instantaneous concentration.

Outputs go to histo/ (NetCDF), images/ (PNG), and tiffs/ (GDAL conversion) beneath the configured output folder. The current main block merges existing monthly histograms; individual histogram generation is commented out.

Country statistics: direction and schema

sum_from_COUNTRY describes waste originating in that country and its destinations, with ocean/beach totals. sum_to_COUNTRY describes waste arriving at that country and its sources. JSON nests these under country keys with from/to objects, totals, and lists of {name, tons, perc}. The parser removes countries without a from object and excludes filenames containing _CBS_.

The CSV is a human-readable sequence of country table blocks rather than a normalized one-row-per-country-pair dataset. The active parser expects semicolon-delimited scenario files; root-level older statistics files are fixed-width, for which separate *_nodecay readers exist.

09 / REPRODUCIBILITYWhat needs attention before execution

This is a collection of research scripts with machine-specific settings. No dependency manifest or lockfile was found in the reviewed code tree. Dependencies inferred from imports include OceanParcels, NumPy, xarray, netCDF4, pandas, GeoPandas, Shapely, Matplotlib, Cartopy, Plotly, Dash, and dash-bootstrap-components. Additional workflows use mpi4py/MPI, Dask/Zarr, pyshp, Kaleido, GDAL, ImageMagick, Ghostscript, and Slurm. Compatible versions are not pinned here.

  1. Unify configuration keys. Reconcile the simulation’s WorldLitter imports with GlobalModel in params.py and active MainConfig.py. Copying an HPC example alone does not fix the mismatch.
  2. Restore data paths and matching metadata. The configured forcing/release/output mounts are absent locally. Select the correct release set, regenerate or locate its country index CSV, and update old absolute repository paths.
  3. Match forcing conventions. The reader extracts the date from the fifth underscore-separated filename token. Check actual filenames, velocity variables, time coverage, coordinate ranges, and whether winds are already included.
  4. Reconcile segment filenames and batch templates. Align shell output folders with the active Python configuration and verify both restart arguments. The extra-year shell template contains un-commented explanatory prose that would be interpreted as commands.
  5. Validate a short run and its merge. Check particle count/order, time endpoints, longitude wrapping, and the selected beach-state behavior before scaling up. Script 2’s initialization assumes multiple segments; a one-segment merge needs separate handling.
  6. Check each reporting input format and units. Use the correct reader for fixed-width versus semicolon files, preserve scenario meaning, and verify histogram scaling and time-boundary overlap before interpreting products.
